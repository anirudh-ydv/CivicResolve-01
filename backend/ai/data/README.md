# CivicResolve Training Data — Sources & Honest Limitations

All images in `manifest.csv` are **real photographs**, not synthetic/generated
images. No mock data is used anywhere in this manifest. Sources:

| Category | Real images | Source | Notes |
|---|---|---|---|
| `pothole` | 320 (of 1,243 available, capped) | [jaygala24/pothole-detection](https://github.com/jaygala24/pothole-detection) (GitHub release, IVCNZ pothole dataset) | Good coverage |
| `graffiti` | 320 (of 805 available, capped) | [mitwapalkhiwala/Graffiti-Detection](https://github.com/mitwapalkhiwala/Graffiti-Detection) | Good coverage |
| `broken_streetlight` | 294 | [Team16Project/Street-Light-Dataset](https://github.com/Team16Project/Street-Light-Dataset), "Not Working" class only | Good coverage |
| `cracked_sidewalk` | 77 | [khanhha/crack_segmentation](https://github.com/khanhha/crack_segmentation) test images | **Below the 150-300 target.** These are general pavement/concrete crack photos, not exclusively sidewalks. Expect weaker performance on this class. |
| `illegal_dumping` | 137 | [garythung/trashnet](https://github.com/garythung/trashnet), "trash" class | **Below target and domain mismatch**: these are studio photos of individual loose trash items on a posterboard, not in-situ street/curb dumping scenes. This is a real but imperfect proxy — flagged here explicitly rather than presented as ideal training data. |
| `damaged_sign` | **0** | *None found* | No real, downloadable dataset for damaged/vandalized signage was reachable from this sandbox. Kaggle's "Damaged Signs Dataset" and a HuggingFace "StreetSignSet" exist but those hosts (`kaggle.com`, `huggingface.co`) are outside this sandbox's network allowlist. A synthetic damaged-sign generator repo was found but was excluded on principle (no synthetic images used). **The model has never seen a single damaged_sign example and will never confidently predict this class** — this is a known, disclosed gap, not a silent failure. |
| `other` (negative class) | 300 (of 1,000 available, sampled) | [EliSchwartz/imagenet-sample-images](https://github.com/EliSchwartz/imagenet-sample-images) | Diverse real photos (animals, food, household objects, vehicles) used to teach the model what is *not* an infrastructure issue, and reused for guardrail testing (Part 1.5) on genuinely unrelated photos. |

**Total: 1,448 real images across 6 of 7 categories.**

## Why not Kaggle/Roboflow?

This sandbox's outbound network is allowlisted to a small set of domains
(GitHub, PyPI, npm, etc.) and does not include `kaggle.com`, `roboflow.com`,
`zenodo.org`, or `huggingface.co`. All data acquisition here used GitHub
repositories that host real image files directly in-repo or as release
assets. This is a real, disclosed constraint of the environment — not a
shortcut taken for convenience.

## Why not ImageNet-pretrained weights?

`download.pytorch.org` (where `torchvision`'s pretrained ResNet50 weights
are hosted) is also outside the network allowlist (confirmed: `HTTP 403,
x-deny-reason: host_not_allowed`). Training therefore uses
`pretrained=False` with a frozen, randomly-initialized early backbone,
fine-tuning only `layer4` + the two heads. This is a materially weaker
setup than real transfer learning, and accuracy is capped accordingly —
see `TRAINING_REPORT.md` for actual measured metrics.

## Severity labels

None of the source datasets include human-annotated severity scores (1-10).
Severity targets during this bootstrap training run are generated by a
**deterministic, per-category heuristic range** (`HEURISTIC_SEVERITY_RANGE`
in `model_pipeline.py`), not by human judgment and not by random noise. This
is a placeholder until real severity corrections accumulate through the
admin-review feedback loop (Part 4) and get used in a retraining pass. The
severity regression head's reported MAE in `TRAINING_REPORT.md` is
therefore MAE-against-heuristic-labels, not MAE-against-ground-truth — this
distinction matters and is called out again there.

## Feedback loop (Part 4)

Admin corrections/confirmations made via `PATCH /api/reports/{id}/review`
are logged to the `training_feedback` table (see `models/report.py`).
`models/export_feedback_for_retraining.py` exports confirmed corrections
into a manifest-compatible CSV for a future retraining pass.

**Recommended cadence:** don't retrain on every single correction - wait
until there are at least `MIN_ROWS_FOR_RETRAIN` (50, configurable) new
corrected rows, since a handful of corrections have outsized/noisy
influence relative to the ~1,448 images in the original bootstrap
dataset. The export script warns and refuses to recommend a retrain
below that threshold, but still writes the file so it can be inspected.
Merging the export into `manifest.csv` and re-running the training
driver is a manual step on purpose - an admin should look at what's
being merged before kicking off compute, especially early on.

## Split

Stratified 70/15/15 train/val/test split per category, seed=42, in
`build_manifest.py` (kept alongside this README for reproducibility).

## Data portability (found and fixed in a later review)

`manifest.csv`'s `filepath` column used to store **absolute paths**
specific to the original build sandbox (`/home/claude/datasets/...`).
That path no longer exists even in that same sandbox, which meant the
training data was effectively unreproducible anywhere else — a fresh
clone of this repo had a manifest full of dead references and no working
way to point at wherever real images actually lived.

Fixed: `filepath` now stores paths **relative to `CIVICRESOLVE_DATA_ROOT`**
(env var, defaults to `backend/ai/data/raw/`), resolved at load time by
`model_pipeline.py`'s `_resolve_image_path()`. To actually regenerate this
dataset for real in a networked environment:

```bash
export CIVICRESOLVE_DATA_ROOT=/path/to/your/data
git clone https://github.com/jaygala24/pothole-detection            $CIVICRESOLVE_DATA_ROOT/pothole_raw
git clone https://github.com/mitwapalkhiwala/Graffiti-Detection      $CIVICRESOLVE_DATA_ROOT/graffiti_raw
git clone https://github.com/Team16Project/Street-Light-Dataset      $CIVICRESOLVE_DATA_ROOT/broken_streetlight_raw
git clone https://github.com/khanhha/crack_segmentation              $CIVICRESOLVE_DATA_ROOT/cracked_sidewalk_raw
git clone https://github.com/garythung/trashnet                      $CIVICRESOLVE_DATA_ROOT/illegal_dumping_raw
git clone https://github.com/EliSchwartz/imagenet-sample-images      $CIVICRESOLVE_DATA_ROOT/other_pool

cd backend/ai/data && python build_manifest.py   # regenerates manifest.csv
cd ../.. && python -m ai.model_pipeline           # real training run
python -m ai.evaluate                             # real evaluation, incl. severity collapse check
```

The exact internal folder layout of each source repo (e.g. whether images
sit directly in the repo root vs. a subfolder) was **not re-verified
against the live repos as part of this fix** — no network access was
available in this environment either. `build_manifest.py`'s `os.walk()`
over each `SOURCES[...]` directory should find image files regardless of
how deep they're nested, but if a repo's structure has changed since the
original data was sourced, check its actual contents before assuming this
just works end-to-end.
